Trabalho Prático 1 — Engenharia de Prompt e Contexto na Prática
1. Descrição do Projeto
O projeto desenvolvido consiste em um jogo de Campo Minado Web, criado com auxílio do Google AI Studio.
O sistema permite que o jogador escolha diferentes níveis de dificuldade e jogue seguindo as regras tradicionais do Campo Minado.
As principais funcionalidades implementadas são:
geração aleatória de minas;
revelação das células do tabuleiro;
exibição da quantidade de minas adjacentes;
colocação e remoção de bandeiras;
contador de minas;
cronômetro;
reinício da partida;
condição de vitória;
condição de derrota;
seleção de dificuldade;
seleção de cenário visual.
Os níveis de dificuldade disponíveis são:
Fácil: 9 × 9, com 10 minas;
Médio: 16 × 16, com 40 minas;
Difícil: 16 × 30, com 99 minas.
Também foram implementados quatro cenários visuais:
Clássico Verde;
Noite;
Neve;
Deserto.
A troca de cenário modifica somente a aparência do jogo, preservando o tabuleiro, a posição das minas, o cronômetro e o andamento da partida.

3. Técnica de Prompt Engineering Utilizada
A técnica de Prompt Engineering escolhida foi o Few-shot Prompting.
Essa técnica foi utilizada porque o Campo Minado possui comportamentos específicos que precisam ser interpretados corretamente pelo modelo.
Foram fornecidos exemplos concretos do comportamento esperado.
Exemplos utilizados
Exemplo 1:Se o jogador clicar com o botão direito em uma célula fechada sem bandeira, o sistema deve colocar uma bandeira nessa célula.
Exemplo 2:Se o jogador clicar novamente com o botão direito em uma célula que já possui bandeira, o sistema deve remover essa bandeira.
Exemplo 3:Se o jogador revelar uma célula que possui zero minas adjacentes, o jogo deve revelar automaticamente as células seguras vizinhas de acordo com as regras tradicionais do Campo Minado.
Exemplo 4:Se o jogador selecionar o cenário Noite, apenas a aparência da interface deve mudar. A quantidade e a posição das minas não devem ser modificadas por causa da troca de cenário.
Justificativa
O Few-shot foi escolhido porque permite fornecer ao modelo exemplos claros de como determinadas interações do sistema devem funcionar.
No contexto do Campo Minado, isso ajudou a reduzir ambiguidades, principalmente em comportamentos relacionados ao uso de bandeiras, abertura automática de células e troca de cenários sem alterar o estado da partida.

4. System Prompt
O System Prompt foi definido antes do início da implementação do projeto.
System Prompt utilizado
Você é um desenvolvedor de software especializado em desenvolvimento web front-end, com foco em HTML, CSS e JavaScript.
Sua função é auxiliar no desenvolvimento de um jogo Campo Minado Web completo, funcional, responsivo e organizado.
Durante o desenvolvimento, siga estas regras:
Utilize HTML, CSS e JavaScript de forma clara e organizada.
Priorize código simples, legível e fácil de manter.
Não utilize bibliotecas ou frameworks externos sem necessidade.
Separe adequadamente estrutura, estilo e lógica da aplicação.
Preserve funcionalidades já implementadas ao realizar alterações.
Não remova funcionalidades existentes sem solicitação explícita.
Explique de forma objetiva mudanças importantes realizadas no projeto.
Evite adicionar funcionalidades que não tenham sido solicitadas.
O jogo deve funcionar diretamente no navegador.
O Campo Minado deverá possuir como funcionalidades principais:
geração aleatória de minas;
revelação de células;
indicação numérica da quantidade de minas próximas;
colocação e remoção de bandeiras;
contador de minas/bandeiras;
cronômetro da partida;
condição de vitória;
condição de derrota;
possibilidade de reiniciar a partida;
níveis de dificuldade Fácil, Médio e Difícil;
seleção de diferentes cenários visuais pelo jogador.
Os cenários visuais iniciais serão:
Clássico Verde;
Noite;
Neve;
Deserto.
A escolha do cenário deve modificar apenas a aparência visual da aplicação, sem alterar as regras, a distribuição das minas ou a dificuldade da partida.
Sempre considere as regras fornecidas pelo usuário e o contexto disponível antes de modificar o código. Quando apenas uma parte do projeto precisar ser alterada, evite mudanças desnecessárias em arquivos ou funcionalidades não relacionadas.
Justificativa do System Prompt
O System Prompt foi criado para estabelecer previamente:
o papel da IA;
o tipo de aplicação;
as tecnologias desejadas;
as funcionalidades obrigatórias;
as restrições do desenvolvimento;
o comportamento esperado durante alterações futuras.
Essa definição ajudou a manter o desenvolvimento dentro do escopo e reduziu alterações desnecessárias no projeto.

16. Conclusão do Teste de Curadoria
O experimento demonstrou que fornecer somente o contexto necessário pode diminuir significativamente o consumo de tokens.
No teste com o arquivo completo foram utilizados 751 tokens de entrada.
Com o contexto curado foram utilizados 308 tokens de entrada.
Isso representou uma redução aproximada de 59% nos tokens de entrada.
O custo estimado considerando tokens de entrada e saída também caiu aproximadamente 53,5%.
O resultado demonstra que a curadoria de contexto pode reduzir o consumo de tokens e o custo das chamadas sem impedir que o modelo receba as informações necessárias para responder à tarefa.
